# Review: four role reviews and what changed

2026-10-16

Four reviewers (Product manager, Architect, Backend/ML engineer, Frontend/UX engineer) read the whole PRD and design and researched the technical claims; 48 findings came back, 3 of them blockers. Three findings were re-verified against primary sources before anything was applied: Anthropic's policy on subscription logins in products, the streaming capability of open-source WhisperKit, and the Claude Code deep-link scheme. Rows marked Applied are already in PRD.md; rows marked Proposed are product decisions left to the owner.

## Decisions left to the owner

- [ ] Scope cut (PM F1): v1 as written is a multi-engineer-year programme for one person part-time. Recommended MVP: capture, live transcript with per-utterance language ID, you-vs-them with per-call labels, post-call outputs via Claude Code with local fallback, hybrid search and ask mode, Markdown export, a single-agent copilot behind a flag. Everything else to v1.x behind evidence. Not applied: the features stay in v1 until this is decided.
- [ ] Council gating (PM F6, Architect F2): ship the council in v1 as the fused mode (one request carries all roles) and allow the parallel mode (one session per agent, per-agent model and effort) as an option; or defer the council to v1.x behind evidence from the single-agent copilot. Applied: fused mode default live, parallel mode available; deferral not applied.
- [ ] Handoff deferral (PM F9): most engineering items from a lead's calls are owned by reports, so Open in Claude Code helps only items the owner does themselves. Not applied; the feature stays in v1 with Copy as the universal path.
- [ ] Voice profiles (PM F3): keep cross-call voice profiles in v1 as opt-in per person with explicit consent (applied), or move them to v1.x entirely (proposed by the PM).
- [ ] Per-turn structured output in a long-lived Claude Code session is undocumented (Architect F8): prototype in M1; fallback is an `emit_card` tool on noter-mcp.

## Architect

| # | Finding | Severity | What changed, or the proposal | Status |
| --- | --- | --- | --- | --- |
| A1 | A product may not run on the user's Claude subscription: Anthropic's [legal page](https://code.claude.com/docs/en/legal-and-compliance) says products and Agent SDK users must use API keys and may not route requests through Free/Pro/Max credentials; only an end user signing into the unmodified binary themselves is exempt | Blocker | API key (`--bare`, Keychain) is the primary path for every automated task; "use my own Claude login" is a personal-use switch with a throttling warning; team release requires API keys or Bedrock/Vertex per user plus Commercial Terms; auth failure drops to local without losing the call | Applied |
| A2 | Six tool-using warm sessions cannot hold the live budget; non-bare `-p` loads `~/.claude` hooks and MCP servers six times | Major | Live tick is one no-tools request (fused mode) by default; tool-using per-agent sessions for post-call reviews or opt-in live parallel mode; isolation flags always passed | Applied |
| A3 | Three processes writing one SQLite file; VACUUM and long jobs stall capture | Major | Core is the only writer; noter-mcp is a thin client over a Unix socket; jobs commit in ≤ 200-row batches and yield during calls; incremental auto-vacuum; nightly checkpoint | Applied |
| A4 | Search depended on the Ollama daemon; memory metric contradicted the routing table ([bge-m3 1.2 GB](https://ollama.com/library/bge-m3), Qwen3 8B 5.2 GB) | Major | bge-m3 runs in-process (CoreML in the engine); Ollama optional for generation; footprint metric split: ≤ 4 GB without a local LLM, ≤ 8 GB with the 8B loaded | Applied |
| A5 | "Noter stores no credentials" was false for indexed remote MCP sources and evidence collection | Major | Stated plainly: OAuth tokens for remote MCP servers in indexed or evidence mode live in the Keychain, revocable on the Sources page; Jira evidence goes through `acli` or the user's own CLI MCP config | Applied |
| A6 | Engine JSON Lines protocol had no back-pressure and shared stdout with logs | Major | Dedicated I/O thread with a bounded queue that drops levels and stale hypotheses; logs to stderr; bulky payloads by file path; `seq` on every event | Applied |
| A7 | Codex `--ephemeral` and `resume` exclude each other ([non-interactive docs](https://learn.chatgpt.com/docs/non-interactive-mode)); API keys are the documented automation path | Major | `--ephemeral` dropped where sessions resume; `CODEX_API_KEY` documented as the automation credential | Applied |
| A8 | Per-turn `structured_output` in a streaming-input session is undocumented | Minor | Prototype in M1; fallback `emit_card` tool | Proposed |
| A9 | sqlite-vec is pre-v1 ([repo](https://github.com/asg017/sqlite-vec)); vec0 filters cannot express "people present" | Minor | Canonical embedding as a BLOB on the row; vec0 tables rebuildable and partitioned by call; over-fetch 4×k and post-filter in SQL; benchmark before promising 100 ms | Applied |
| A10 | "Engine has no network entitlement" is not a build property without the App Sandbox | Minor | Engine sidecar is sandboxed with audio-input only and no network entitlement; CI network test stays | Applied |
| A11 | Non-activating call screen needs NSPanel, not NSWindow | Minor | Both surfaces built on tauri-nspanel; `set_content_protected(true)` for screen-share exclusion | Applied |
| A12 | Local fallback cannot meet two minutes on a base M5 (≈ 26 tok/s for 8B) | Minor | Metric split cloud ≤ 2 min / local ≤ 10 min; local uses 8B, summary first, role reviews in the background | Applied |
