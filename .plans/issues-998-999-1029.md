Noter_0.24.0_aarch64.dmg, 14,907,987 bytes, SHA256
5be9c273c16730b4f6039fc9b951ab2b5efe367f1818465547d3012b8a1a31ff):

for both Noter.app and its noter-engine. The app's actual signed entitlements
include the literal TEAMID.ai.noter application group; the engine has the same
group plus app-sandbox=true. The locally built debug test app is linker-signed
ad hoc, has no team and carries no entitlements. Thus the signature/entitlement
difference is verified on artifacts, rather than inferred from the entry point.
The release was never executed; this inspection does not independently reproduce
the owner's filesystem denial. REA bound the DMG identity; its DMG extraction
reader was unavailable, so hdiutil mounted it read-only for codesign inspection
and detached it afterwards.

Source remains consistent with those observations: Noter.entitlements contains
the literal placeholder and engine/scripts/sign.sh substitutes TEAM_ID only
for the engine, defaulting to TEAMID and an ad-hoc identity. No signing policy,
credentials, entitlements or release configuration changed. #998 must stay open
pending the owner's distribution/signing decision.
