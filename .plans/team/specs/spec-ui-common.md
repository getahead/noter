- Your worktree is yours alone. Branch `lane/ui/<feature>` from fresh `origin/main` (discard the stale local branch). - Tests first (a failing-test commit, then the code). Markers `// @cpt-<kind>:<id>:p1` on the line before the code, IDs only from `**ID**:` lines; tick every CDSL box you implement. Never remove markers, skip tests, lower thresholds, add coverage exclusions, edit generated files, baselines or harness files (`harness/`, `scripts/`, `.github/`, `justfile`, test configs).
- E2E: your feature's `tests/e2e/m1-<feature>-ui.spec.ts` exists on `origin/lane/ui/e2e-m1` (ui-e2e's, tests first, 112 tests over 8 files, plus `tests/e2e/support/app.ts` and `support/native-alert.ts` changes; ui-e2e rebases it on main today and sends the SHA). Cherry-pick your file and what it needs into your branch; adjust locators to your markup, never the copy, commands, arguments or story titles. It must pass on the fake core and with `NOTER_CORE=stdio` (real core). Fake-core or contract gaps → `--type escalation` to the Teamlead (backend owns `src/core/fake/**`); do not edit the fake.
- Strings through the catalogue (`i18n/en.ts`, no-concat lint), colours through tokens, primitives from `src/ui/primitives`, banners from `src/ui/feedback`, markup with the prototype's `data-component`/`data-region` IDs. No performance scenarios (owner, 24 Oct). Screenshot baselines only via the `update-screenshots` label; the designer approves.
- Done = plain `just gate` exit 0 (real exit code, no lockf wrapper). Flow: draft PR (Conventional Commit title, body: what, how to verify, spec items ticked) → `send --type status` with the PR number → ui-qa (+ designer for visuals) run → fix every QA FAIL item in the PR → `just gate` → `/cf-sdlc-pr-review <N>` with `/ponytail-review` merged in → `just review-publish <N>` ONLY after the Teamlead's "go #N". Loop on REQUEST CHANGES. Never merge by hand; never rebase/"Update branch" without a conflict.
- Before opening a PR: `gh pr list --state open | wc -l` < 10 across the repo (shared with backend) and you have ≤ 2 open; finish before starting. #129 (release) is the owner's.
- Messages (preamble commands): heartbeat every 5 min with a phase; `check` at every checkpoint; `ask` only for a question you cannot proceed without; `worker_done` once per task naming the PRs. Product/spec ambiguity → tell the Teamlead (routes to HoD). Keep every message to a few lines.
- Middle developers (Sonnet): after two honest attempts at a red `just gate`/CI check, blocking finding or QA FAIL, send the Teamlead the failing output; a senior pairs with you until green.
- Clear context between tasks: when your task is done, write `_team/handoff-ui-<name>.md` (≤ 30 lines: branch, PR, what is left) and send `worker_done`.
