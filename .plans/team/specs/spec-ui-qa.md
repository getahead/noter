# ui-qa (Sonnet 5.5, read-only) — per-PR QA for the UI M1 team (standing task)

Worktree `~/orca/workspaces/noter/ui-qa` (keep it detached at origin/main; it holds untracked, unapproved primitives screenshots from M0 that you must neither commit nor delete: test PRs in a temporary worktree, `git worktree add /tmp/ui-qa-prN pr-N`, as your predecessor did). Read `spec-ui-common.md`, `_team/handoff-ui-qa.md` and `_team/ui/qa/M0-charters.md` §0 (per-PR procedure) and §2 (cross-cutting checks). Never push, commit or merge; your only GitHub writes are the `QA: PASS|FAIL` PR comments.

**Target:** every UI M1 PR (call-window, live-transcript, dialogs-host, library-calls, menu-bar, call-page-frame, record-prompt, notifications, ui-e2e's native tests) gets a PASS/FAIL report with evidence before the Teamlead gives its "go". The Teamlead sends you PR numbers (`check` for them); you may start on any new open UI PR you see (`gh pr list --state open`).

**Change, per PR:** fetch `origin pull/<N>/head:pr-<N>`, merge main locally, `export NOTER_CORE_CMD=...` (common spec) and run `just gate` (real exit code); then check: (a) markers only on `[x]` CDSL items and every ticked item has a marker; (b) tests first per commit (failing test before code); (c) the feature's `m1-<feature>-ui.spec.ts` from `origin/lane/ui/e2e-m1` is in the PR with its story titles intact and passes on fake and `NOTER_CORE=stdio`; (d) no skipped tests, no coverage pragmas, no baseline/golden/harness edits, no perf scenario files (owner: no performance tests); (e) lane paths only; (f) strings through the catalogue, colours through tokens, `data-component`/`data-region` IDs from the prototype; (g) behaviour vs the FEATURE spec and prototype (drive it with Playwright on the fake: `_team/ui/qa/tools/`), including keyboard-only and Reduce Motion; (h) the decisions the PR must apply (D-15/D-18 call-window, D-16 call-page-frame, D-31 dialogs, D-29/D-35 library, D-32 transcript). Report `_team/ui/qa/<N>.md` (PASS/FAIL, commands, exit codes, failing file:line, exact fix) + the one-line PR comment, and `send --type status --subject "ui-qa: #N PASS|FAIL"` to the Teamlead. Re-test after fixes on request.

**Acceptance:** no UI M1 PR is published without a QA report; FAIL items were reproduced and are concrete. Work the queue your dispatch names; after each PR run `check` for new numbers; when the queue is empty send `worker_done` (the Teamlead re-dispatches you with the next queue). Never idle at the prompt without `worker_done`.
