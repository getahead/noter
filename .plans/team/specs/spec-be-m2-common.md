# Common rules for every backend M2 worker (read with your own spec)

- Read, in this order: `CHARTER.md` (Engineering rules, Middle developers, LOW-COST MODE, BACKEND M2), `PLAN-be-m2.md` (decisions TL-12..TL-23, order, owners), `PLAN-be-m1.md` › decisions TL-1..TL-11 and the HoD ratification block, then the repo's `CLAUDE.md`, `docs/DEVELOPMENT.md`, `docs/HARNESS.md`, your FEATURE spec in `docs/features/core/`, and the DESIGN-core sections it cites (`docs/DESIGN-core.md`: 3.1 Domain Model, 3.2 Component Model, 3.3 API Contracts, the `cpt-noter-dbtable-*` entries). `handoff-be-<you>.md` has your predecessor's lessons (the code it describes is on main).
- Every shell starts with `export PATH=/opt/homebrew/bin:/usr/bin:$PATH NOTER_E2E_LOCK=$HOME/projects/noter-wt/.e2e.lock`. Orca: `/Applications/Orca.app/Contents/Resources/bin/orca`. Real-core E2E and story tests: `NOTER_CORE=stdio NOTER_CORE_CMD="$PWD/target/debug/noter-core-harness --fixture world"` (the flag is required). `just setup` once if your worktree's `node_modules`/toolchains are stale.
- Your worktree is yours alone; its branch is stale: start with `git fetch origin && git checkout -B lane/<lane>/<topic> origin/main`. One lane per branch (pre-commit lane guard: `harness/harness.toml [lanes]`; core = `crates/**` except noter-protocol/noter-native/noter-engine-client, plus `apps/desktop/src-tauri/**`; engine = `engine/**`, noter-engine-client, noter-native, `scripts/models/**`; contract = noter-protocol, `contracts/**`, `apps/desktop/src/core/**`, `apps/desktop/tests/conformance/**`). A change that must cross lanes by construction goes on a plain branch (no `lane/` prefix), QA-first, and you tell the Teamlead (M1 lesson). Never bare `git stash`; WIP commits instead. Never `pkill -f`/`killall`.
- Tests first (a failing test commit, then the code). Markers `// @cpt-<kind>:<id>:p1` on the line before the code, IDs only from `**ID**:` lines; tick the CDSL step boxes you implement in the same PR (a parent is `[x]` only when every nested step is). Never remove markers, skip or `#[ignore]` tests, lower thresholds, add coverage exclusions, edit generated files (`contracts/**`, `bindings.ts`: change `crates/noter-protocol`, `just contract-regen`) or harness files (`harness/`, `scripts/harness/`, `.github/`, `justfile`, test configs, `deny.toml`). A new IPC command or story never happens in M2 (all 41 commands and 10 stories are already in `harness/milestones.toml`).
- A PR that adds a crate or a dependency must also update `apps/desktop/src-tauri/Cargo.lock` (the Tauri host has its own lock file and CI runs `cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml`): run that command locally without `--locked` once, keep only your dependency closure in the lock diff, commit it in the same PR. Migrations are Rust lists in `crates/noter-db/src/migrate.rs` (owner + version): a crate that owns tables passes its own list to `Store::open`; never reuse a version number already on main in the same owner's list.
- Timers on tokio paused time, `Clock` for timestamps (TL-4); every write through the change-log write path except capture data (TL-1); typed errors from `noter_protocol::error`.
- Done = plain `just gate` exit 0 (check the real exit code). Then push, `gh pr create` (Conventional Commit title; body: what, how to verify, which spec items it ticks, tests-first evidence), run `/cf-sdlc-pr-review <N>` with `/ponytail-review` merged in, then `just review-publish <N>` (auto-merge). Loop on REQUEST CHANGES. Never merge by hand. Do not rebase or "Update branch" a PR without a conflict. If CI is red for a reason outside your diff, say so in `worker_done`; the Teamlead handles it.
- Before opening a PR: `gh pr list --state open` must be < 10 across the repo and you must have < 2 open. Finish before starting.
- LOW-COST MODE: one task per dispatch; when your PR is published (review published, auto-merge on), send `worker_done` (PR number, what it ticks, what is left, any question) and stop; do not poll CI, do not idle. The Teamlead watches CI and QA and re-dispatches you with a fresh spec for fixes or the next slice. Heartbeat every 3 min with a phase while working; `ask` for a blocking question (product/spec ambiguity included: the Teamlead asks the coordinator, HoD is not running); `check` at every checkpoint. One-line messages.
- Middle developers (Sonnet): after two honest attempts at a red `just gate`/CI check, blocking review finding or QA FAIL, send the Teamlead the failing output; a senior pairs with you until it is green.
- QA checks every PR; answer QA FAIL items in the PR, not in chat.
